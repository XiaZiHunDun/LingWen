# Phase 99.1 — Fix pnpm Setup Version Conflict

> **Date**: 2026-08-24
> **Phase**: 99.1
> **Source**: Phase 99 implementer discovery (`1772a86f`) — CI fails at `Setup pnpm` step
> **Status**: Design

---

## 1. Context

Phase 99 promoted knip to hard-blocking CI gate (`1772a86f`). Post-merge, every push fails at the `Setup pnpm` step with:

```
Error: Multiple versions of pnpm specified:
  - version 9 in the GitHub Action config with the key "version"
  - version pnpm@9.0.0 in the package.json with the key "packageManager"
Remove one of these versions to avoid version mismatch errors like ERR_PNPM_BAD_PM_VERSION
```

This is **pre-existing** (not caused by Phase 99). All recent master pushes (Phase 100, Phase 95 plan, earlier commits) failed at the same step — CI was effectively dead before Phase 99 too.

**Affected workflows (6 files, 11 `pnpm/action-setup@v4` invocations):**

| File | Count |
|------|-------|
| `dashboard-frontend-ci.yml` | 5 |
| `dashboard-e2e-smoke.yml` | 2 |
| `dashboard-frontend-quarantine.yml` | 1 |
| `dashboard-frontend-llm-e2e.yml` | 1 |
| `dashboard-frontend-coverage-pages.yml` | 1 |
| `test.yml` | 1 |
| **Total** | **11** |

**Pattern repeated in all 11 sites:**
```yaml
      - name: Setup pnpm
        uses: pnpm/action-setup@v4
        with:
          version: 9
```

**Conflict:** `pnpm/action-setup@v4` requires single source of truth. Current pattern specifies `version: 9` AND `package.json#packageManager: "pnpm@9.0.0"`. `pnpm@9.0.0` is an exact version; `9` is major-only. The action refuses to pick — hence the error.

**Why now is the right time:**
- Phase 99 made knip a real gate, but CI can't observe it without Setup pnpm working.
- Without this fix, future CI runs are useless — every push fails before knip.
- The fix is mechanical (11 identical edits) and low-risk (revert = 1 commit).

---

## 2. Goal

Delete `version: 9` from all 11 `pnpm/action-setup@v4` invocations, so `package.json#packageManager: "pnpm@9.0.0"` is the single source of truth. CI then runs Setup pnpm successfully, and Phase 99's knip gate becomes observable.

---

## 3. Non-Goals

- **NOT** changing the pnpm version (stays at 9.0.0).
- **NOT** modifying `package.json` (the `packageManager` line is the correct source of truth and stays).
- **NOT** changing `pnpm/action-setup@v4` to a different action version (current `v4` is the latest and supports `packageManager` auto-detection).
- **NOT** adding any other workflow changes (lint, cache, Python setup, etc. stay as-is).
- **NOT** modifying `actions/setup-node@v4` configuration (cache, node-version stay as-is).
- **NOT** adding tests. CI behavior is the test.

---

## 4. Design

### 4.1 Change Set

11 identical edits, one per `Setup pnpm` step. Each edit:

**Find (4 lines):**
```yaml
        uses: pnpm/action-setup@v4
        with:
          version: 9
```

**Replace (2 lines):**
```yaml
        uses: pnpm/action-setup@v4
```

The `with:` block and its `version: 9` line are deleted. The action then auto-detects the version from `package.json#packageManager` (pnpm@9.0.0).

`name: Setup pnpm` line stays unchanged.

### 4.3 Risk Analysis

- **Behavior change**: Minimal. `pnpm/action-setup@v4` docs explicitly support `packageManager` auto-detection. Removing `version` triggers that path. If for any reason auto-detection fails on GitHub's runners, the action fails Setup pnpm again — but the failure is now a *different* error, easier to debug.
- **Cache compatibility**: `actions/setup-node@v4` uses `cache: 'pnpm'` + `cache-dependency-path:`. These depend on a working pnpm binary. Removing `version: 9` should not affect cache behavior — cache key is derived from pnpm-lock.yaml, not pnpm version.
- **Local dev impact**: Zero. Engineers running pnpm locally use `package.json#packageManager` via Corepack. No workflow change affects local dev.
- **Rollback cost**: 1 atomic revert + push. Trivial.

### 4.4 Verification Strategy

After merge (Task 5):
1. CI run on `dashboard-frontend-ci.yml` should pass `Setup pnpm` step.
2. CI run should reach `Setup Node.js`, `Install dependencies`, `Run lint suite`, `Run knip (dead-export detection)`, `Typecheck tests (relaxed)`, etc.
3. **`Run knip (dead-export detection)` step should FAIL** (intended — proves Phase 99 gate works end-to-end now that Setup pnpm passes).
4. All other steps (lint, typecheck, build, etc.) should pass.

For confirming Setup pnpm itself works:
- Inspect CI logs: the `Setup pnpm` step should show "Successfully setup pnpm X.Y.Z" with X.Y.Z = 9.0.0.

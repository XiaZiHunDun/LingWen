# Phase 102.2 — Remove Unused devDep + Add knip Binary to Config

> **Status**: Design

## 1. Context

After Phase 103.1 resolved `Unused files`, knip's remaining small-batch findings are 1 unused devDep and 1 unlisted binary. Both are 1-line config-level fixes.

### Issue 1 (1 unused devDep): `eslint-plugin-local-rules`

- `apps/dashboard/package.json` declares `"eslint-plugin-local-rules": "^1.1.0"` in devDependencies.
- The `eslint-plugin-local-rules` npm package's purpose: auto-load local rule files named `eslint-local-rules{.js,.cjs}` (or `eslint-local-rules/index.js`).
- Actual usage in `apps/dashboard/eslint.config.js:7`: `const localRules = require('./eslint-local-rules.cjs')` — **direct require**, NOT via the npm plugin's auto-discovery.
- The comment header in `eslint-local-rules.cjs` explicitly references the naming convention but the config bypasses the plugin.
- Therefore the devDep is unused.

### Issue 2 (1 unlisted binary): `knip` itself

- Root `package.json` declares `"knip": "^6.32.2"` in devDependencies.
- `knip` is invoked via `pnpm exec knip` (root, after Phase 102.1 delegation) and via `pnpm exec knip --config apps/dashboard/knip.json` (CI).
- knip 6+ tracks "binaries" used in scripts/workflows vs declared in package.json#binaries config.
- The binary `knip` is used but not declared in `apps/dashboard/knip.json#binaries` → flagged as "Unlisted binaries (1)".

---

## 2. Goal

Resolve the 2 remaining small-batch knip findings:
- Remove the unused `eslint-plugin-local-rules` devDep
- Declare `knip` as a known binary in `apps/dashboard/knip.json`

End-state target: knip output contains only `Unused exported types (10)` (Phase 104 scope) and `Unused dependencies (1)` (Phase 105a scope). The `Unused devDependencies (1)` and `Unlisted binaries (1)` categories drop to 0.

### 4.2 Risk Analysis

- **Build risk**: None. Removing `eslint-plugin-local-rules` doesn't affect the build (Vite ignores devDeps).
- **Test risk**: Low. The `pnpm install` may update `pnpm-lock.yaml`. Existing tests use the local rules via direct require, not the npm plugin, so they're unaffected.
- **Lint risk**: None. `eslint.config.js` uses `require('./eslint-local-rules.cjs')` (direct require) — the npm plugin was never involved in loading the rule.
- **knip config risk**: None. Adding `"binaries": ["knip"]` to knip.json just tells knip "I know about this binary; it's used". No semantic change.

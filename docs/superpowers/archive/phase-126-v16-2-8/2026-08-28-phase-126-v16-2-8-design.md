## 3. Design decisions

### 3.1 Naming convention: NO `Creator` prefix

All 5 new typed wrappers use **new names without `Creator` prefix** (matching v16.2.1+ convention):
- `health.ts`: `fetchOverview`, `fetchChapters`, `fetchProductionRecords`, `fetchProductionRollup`, `fetchProductionCostTrend`, `fetchHealth` (6 funcs)
- `decisions.ts`: `fetchPendingDecisions`, `fetchAllDecisions`, `resolveDecision`, `deferDecision`, `cancelDecision` (5 funcs)
- `cvg.ts`: `fetchRipples`, `fetchRippleDetail`, `applyRipple`, `rejectRipple`, `fetchRippleStats`, `fetchReferenceGraph`, `fetchRippleAudit`, `rollbackRipple`, `fetchRippleCascade`, `fetchRipplePreview`, `fetchCascadeRuns`, `fetchAllCascadeRuns`, `cancelCascadeRun`, `fetchCascadeWithDepth` (14 funcs)
- `workflows.ts`: `fetchWorkflows`, `runWorkflow`, `resumeWorkflow`, `fetchActiveWorkflow`, `fetchWorkflowGraph` (5 funcs)
- `studio.ts`: `listStudioProjects`, `setStudioActive`, `fetchStudioSummary`, `fetchStudioQuality`, `fetchStudioQualityReport`, `fetchStudioProseDiff`, `fetchStudioProseJudge`, `studioProductionPreflight`, `studioProductionRun`, `fetchStudioActiveBatchJob`, `fetchStudioBatchJob` (11 funcs)

**Rationale**: matches the typed-wrapper convention established in v16.2.1 (Phase 126 volume T3) where `fetchCreatorVolumeTemplates` → `listVolumeTemplates`. Also aligns with the new architecture where the api/ namespace is no longer "creator-specific" (it's a project-wide API client).

### 3.2 Signature preservation

Each new typed wrapper function preserves **exact runtime behavior** of the legacy .js export:
- Same URL path (e.g. `/workflows/list`, `/decisions/pending`)
- Same query parameter encoding
- Same HTTP method
- Same return type shape (typed as `Promise<unknown>` if no DTO exists, else `Promise<T>` where T is shared contracts DTO)

NO zod runtime validation (per v16.2.1 §5.1 lesson 3). NO `/api/` prefix in code (per v16.2.1 §5.1 lesson 4).

### 3.3 Dead code deletion in T5

`mergePreset.js`'s 4 dead functions (DiffCollab + Wizard helpers) are **deleted without ceremony**. They have no consumers (per `grep -r "fetchCreatorDiffCollabNotes" apps/dashboard/src` only matches definition + re-export). If they're needed later, they'll be added to `onboarding.ts` as part of the onboarding migration.

### 3.4 `useCreatorSettings.js` refactor strategy

The composable uses dynamic imports for some merge-preset operations (e.g. `await import('../api/index.js')` to lazy-load). Refactor strategy:
1. Replace static Creator-prefixed imports with static non-prefixed imports from `@/api/settings`
2. Replace dynamic `await import('../api/index.js')` blocks with dynamic `await import('@/api/settings')` blocks
3. Verify panelContext shape unchanged (downstream consumers depend on it)
4. Existing `useSettingsHistory/useMergePresets/useSettingsDocs` submodules remain as-is (already migrated)

This is a **mechanical rename**, not a behavior change. Per v16.2.7 §5.1 lesson 2 (name collision), carefully audit the import block to ensure no shadowing.

### 3.5 Test mock pattern

Per v16.2.7 §3 lesson 1 (re-export shim mocks don't propagate), composable test mocks MUST target both:
- The legacy barrel (if still used elsewhere in the composable)
- The new typed wrapper (after migration)

For composables that fully migrate (e.g. `useTodayHub.js` → all typed wrappers), mocks target typed wrapper modules only. For `useCreatorSettings.js` which still uses some legacy patterns, mocks cover both targets.

### 3.6 No new DTOs

This phase is purely **frontend refactor**. No backend Pydantic changes, no codegen runs needed, no DTO contracts added. The 5 new typed wrappers use **inline interface declarations** with `Promise<unknown>` returns where the backend payload shape is not yet known to shared contracts.

If downstream consumers need typed responses, that becomes v16.4+ work (DTO schema audit).

3. **Dead code in legacy modules**: 4 functions in `mergePreset.js` have zero consumers. Per v16.2.7 §5.1 lesson 6, delete without ceremony. If later needed, add to typed wrapper in the appropriate subdomain.

4. **Test mock pattern**: Per v16.2.7 §3 lesson 1, when composable migrates from barrel to typed wrapper, test mocks must update to target typed wrapper. For full migrations, this is straightforward.

5. **Dynamic imports**: `useCreatorSettings.js` uses dynamic imports inside async functions. Mechanical replacement, but verify each dynamic import resolves correctly.

### 6.1 触发回滚的信号

| 信号 | 触发条件 | 回滚时机 |
|---|---|---|
| T8.1 pytest 失败 | > 0 个测试 fail | 立即 |
| T8.2 vue-tsc 有 errors | > 0 个 errors | 立即 |
| T8.3 vitest 失败 | > 0 个 tests fail | 立即 |
| 本地启 dev server 500 | curl `localhost:8765/health` 返回非 200 | 立即 |
| CI 整体 fail | 任何关键 job fail | 立即 |

### 6.2 回滚步骤(Q1=A,single-step 模式)

1. `git log --oneline -5` — 找 v16.0 commit hash
2. `git revert <v16-0-commit-hash>` — 单 commit revert(不强制历史)
3. 跑 `uv sync` (确认 revert 后能正常 lock)
4. 跑 `pytest tests/ -q` — 必须回到 73 passed
5. 跑 `cd apps/dashboard && pnpm vitest run --reporter=dot` — 必须回到 1731 passed
6. 本地启 dev server,验证 `/health` 200
7. Push revert commit

### 6.3 回滚时间预算

| 步骤 | 预期时长 |
|---|---|
| Detect failure | ≤ 30 min(CI 信号) |
| Diagnostic | ≤ 2 hours(确认是 uv config 问题还是单纯代码问题) |
| Patch(不撤整个 phase) | ≤ 1 day |
| Full revert(走 git revert) | ≤ 30 min |

**SLA**: v16.0 失败 → 24 小时内撤掉或修掉。

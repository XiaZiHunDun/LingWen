## 2. Critical Implementation Details

### 2.1 T2.1.a — mode.py move (closes v16.2.4 §5.1 carryover)

The v16.2.4 content migration placed `shared/mode.py` in `lingwen_creator/shared/` — but this violated the layering invariant (infra MUST NOT import lingwen_creator). infra/project_config.py and infra/project_init.py had been importing `lingwen_creator.shared.mode`.

The fix:
1. Move mode.py content to `packages/lingwen-shared/src/lingwen_shared/mode.py` (true leaf)
2. Convert `packages/lingwen-creator/src/lingwen_creator/shared/mode.py` to a back-compat shim (re-exports all symbols)
3. Update 2 infra imports to use `lingwen_shared.mode` directly

This unblocked the `layer_dependencies` contract (infra → lingwen_creator violation surfaced by import-linter).

### 2.2 T3 — ESLint no-restricted-imports pattern syntax

The `patterns.group` field uses minimatch glob. Two patterns are needed for full coverage:
- Literal name: `infra`, `lingwen_creator`
- Slashed: `infra/*`, `infra/**`, `lingwen_creator/*`, `lingwen_creator/**`
- Cross-prefix: `**/infra`, `**/infra/*`, `**/infra/**` (for `import` from anywhere with these substrings — but `@/` already handles via Vite alias)

Confirmed via 13-case test (`tests/eslint-rules/no-restricted-imports.test.cjs`).

### 2.3 T4.1 — Hoisted mock pattern (v16.2.8 §3 lesson 1)

After barrel consumer migration, the existing test mocks for `vi.mock('../../src/api/index.js', ...)` no longer fire because production code now imports typed wrapper directly. Per the hoisted mock pattern:

```ts
const cvgMocks = vi.hoisted(() => ({
  fetchCascadeRuns: vi.fn(),
  cancelCascadeRun: vi.fn(),
  fetchCascadeWithDepth: vi.fn(),
}))

vi.mock('../../src/api/index.js', () => ({
  fetchCascadeRuns: cvgMocks.fetchCascadeRuns,
  ...
}))

vi.mock('@/api/cvg', () => ({
  fetchCascadeRuns: cvgMocks.fetchCascadeRuns,
  ...
}))
```

Without hoisting, each `vi.mock` factory creates fresh `vi.fn` per module path → assertions on barrel miss calls through typed wrapper. Updated 6 page-level tests with this pattern.

## 3. Lessons Learned (5)

1. **import-linter `forbidden_modules` wildcard syntax**: glob `infra.creator_*` rejected ("wildcard can only replace a whole module"). The fix is file-existence check in `check_import_linter.py` (glob `infra/creator_*.py` returns 0). import-linter's glob matches `infra.creator.*` (sub-packages), not `infra.creator_X` (top-level module). **Different tools for different things.**

2. **import-linter `layers` ordering**: layers[0] = top (api_gateway), layers[N] = bottom (infra). Higher may import lower, lower MUST NOT import higher. **Easy to invert by accident.**

3. **Mode.py placement**: cross-subdomain utility must be in `lingwen_shared` (true leaf), NOT `lingwen_creator/shared/`. v16.2.4 spec assumed the latter; only surfaces when import-linter layer contract enforces it. **Architecture invariants must be enforced to be discovered.**

4. **ESLint `no-restricted-imports` doesn't resolve `@/` alias**: knip doesn't either. Workaround: keep typed wrappers in `knip.json` ignore list with note "knip can't see @/ alias resolution". **Acceptable advisory; CI gate is ESLint, not knip.**

5. **Hoisted mock pattern re-confirmed**: 6 page tests broken after T1 migration. The fix is mechanical but MUST be done atomically per test (each barrel mock + typed wrapper mock shares vi.fn instance via `vi.hoisted`). **Future barrel → typed wrapper migrations should plan this upfront.**

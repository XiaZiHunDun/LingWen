## 3. Lessons learned

1. **Re-export shim mocks don't propagate**: T6.A revealed that when composables migrate from barrel `@/api/index.js` to typed wrapper `@/api/content`, the test's barrel mock no longer intercepts the typed wrapper import. Per v16.2.5 §5.1 lesson 3 — test mocks MUST also be added for typed wrapper modules. Pattern: parallel `vi.mock('../../src/api/{index,content}', () => ({...}))` blocks linked to same hoisted `xxxMocks` variable.

2. **Name collision after rename**: T6.A surfaced a real bug in `useProductPreferences.ts` — the composable had `import { saveCreatorPreferences } from '@/api/content'` AND `import { saveCreatorPreferences } from '../../utils/creatorPreferencesStorage.js'`. The second import shadowed the first, causing the API save to silently call local storage instead. Fix: alias local-storage import as `saveCreatorPreferencesLocal`.

3. **Shadow bug in legacy composables**: T6.B found `useTemplateSync.ts` had `async function applyVolumeTemplate()` locally shadowing `import { applyVolumeTemplate } from '@/api/volume'`. After T6.B rename `applyCreatorVolumeTemplate` → `applyVolumeTemplate`, the local function shadowed the import → infinite recursion in test (Maximum call stack). Fix: alias import as `apiApplyVolumeTemplate`.

4. **DTO schema drift**: T6 typed wrapper migration surfaced **pre-existing** DTO contract bugs (CreatorModelsResponse had `providers` field instead of `models + default_model`). Typed wrapper strict types exposed them. T8 added `as unknown as` casts in composables to preserve runtime behavior; full DTO schema audit is **separate work item** (carryover to v16.4).

6. **shim existence ≠ back-compat**: `test_legacy_import_paths_still_work` tests in pkgs were comparing `lingwen_creator.X.Y as LegacyFoo` to `lingwen_creator.X.Y` (same module, tautological). Rewritten to `test_legacy_shim_deleted` asserting ModuleNotFoundError.

7. **Test mock patterns must be hoisted together**: For split barrel + typed-wrapper mocks, both mock factories must reference the same `vi.hoisted(...)` variable so test assertions (`mockResolvedValue`, `toHaveBeenCalledWith`) target the right mock.
